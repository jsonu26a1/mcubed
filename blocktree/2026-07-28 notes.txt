There's a lot of cases we need to handle for the `remove()` algorithm; in my rewrite, I opted to define a type `enum Case` with variants { LeftToCurrent, RightToCurrent, SplitCurrent }, which correspond to cases 1, 2, 3 in my previous implementation. however, now I think the variants should look like: { BalanceFromLeft, BalanceFromRight, MergeThree, MergeTwo }. LeftToCurrent is renamed to BalanceFromLeft (same for Right* variant), SplitCurrent is renamed to MergeTree, and MergeTwo is added to handle cases when we're removing from a leaf that is the first or last node in it's parent; when the leaf is below the minimum items, and it's only adjacent sibling is exactly at the minimum of items, we cannot BalanceFrom[Left,Right], because the sibling cannot spare any items, so we must do `MergeTwo`.

when a leaf has both left and right siblings, we check if there's space to split the leaf (MergeThree), so the `MergeTwo` case is only when leaf is the first or last node. I ended up making `MergeTwo` into `MergeWithLeft` and `MergeWithRight`
